## 3. 分かったこと（前提として使う）

### 3.1 「同じページ」= 同じオリジン
- オリジン = `https://` ＋ ドメイン ＋ ポート。ブラウザは**同じオリジンどうしだけ**中身（変数・localStorage）を読み合わせる。
- 別のサイトのタブからは読めない。同じオリジンの別のタブ・**ブラウザの拡張機能**からは読める。
- **GitHub Pages は同じアカウントの全 repo が同じオリジン**（`https://rh-rep.github.io`。`/bubbles-todo/` はオリジンに入らない）。同じアカウントで別の Pages を出すと、そこからキーを読める。
- 同じオリジンの中では、ファイル・HTML を分けても隔離できない。sandbox の iframe・`data:`・`blob:` は名無しのオリジンで、保存場所が無い。

### 3.2 送り先の決め打ち（connect-src）は柵として完全でない
- Solana の公式 RPC は誰でも書ける公開の掲示板。悪いコードは自分の財布でキーをチェーンに書き出せる。
- WebRTC（`js/p2p.js`）は connect-src の対象外。`webrtc 'block'` は仕様にあるが主なブラウザで効くか未確認。
- → **守りの主は「悪いコードを動かさない」**（外部依存ゼロ・script-src 'self'・文字を HTML にしない）。

### 3.3 暗号化して置いても「使う時」は守れない
- 使う時、平文はページの変数（メモリ）にある。返事が返るまで数秒〜数十秒、まとめて使うならその間ずっと。
- そのとき同じオリジンで悪いコードが動いていれば読める（fetch をすり替えて横から写す「待ち伏せ」も可）。
- 悪いコードは本物そっくりのパスキーの確認を出せる。触れると元が渡る。合言葉なら打った合言葉自体が取られる。
- 防げるのは「開いた時に1回だけ動いて終わるコード」と「保存場所の丸ごとの持ち出し」。**盗まれる機会を減らすだけで、盗まれなくはしない。**

### 3.4 ブロックチェーンの財布の秘密鍵
- **端末に置いていない**（暗号化したものも無い）。使う時にパスキーの PRF か合言葉（PBKDF2 60 万回）から 32 バイトの「元」を出し、HKDF で毎回計算する（`js/chain.js` の `keysFromRoot`）。
- 元から 3 つ（財布の秘密鍵・記録の鍵・共有の鍵）が出る。**元が取られると 3 つとも取られる。**
- API キーから財布の元を作るのは勧めない（キーを作り直すと財布が変わる・キーが漏れると財布も漏れる）。

### 3.5 置き場（サーバー・GitHub Pages）が止まったら
- 一度開いた端末は使える（service worker が Cache Storage から先に出す。`sw.js`）。止まるのは新しい版と新しい端末。
- Cache Storage は**ファイル1つずつの写し**（住所 → 中身）で、版ごとに `bubbles-<版>` の棚。記録（localStorage）とは別の場所。
- 記録と保管庫が消え、かつ置き場が止まっていると開き直せない → 引っ越しのファイル・CSV・チェーンのバックアップで控える。
- ブロックチェーンに中身を置いても、ブラウザは https の住所からしか開けないので、**オリジンは間に立つ住所**（読み込み係・IPFS のゲートウェイ）になる。版ごとにオリジンが変わる方式だと記録が毎回空になる。Solana は 1 回約 1.2 KB で、アプリ全体は現実的でない。

### 3.6 ローカルで完結できるか
| 端末 | 方法 | 外に要るもの |
|---|---|---|
| Android | 今の app（中身を app に入れて配る） | 無し |
| Mac・PC | 手元で server.py（`start.command`） | 無し |
| iPhone ホーム画面 | https の置き場から一度追加 | 最初の1回と更新時だけ https の置き場（http だと service worker・パスキー・WebCrypto が使えない） |
| iPhone ネイティブ | iOS の app に包む | Xcode。無料登録は 7 日ごとに入れ直し |
AI だけはどの形でも Anthropic への通信が要る。

## 4. 対策の案

| 案 | 中身 | 盗まれるか | 使えなくなる所・手間 |
|---|---|---|---|
| A | キーを自分のサーバーに置き、AI はサーバー経由 | 盗まれない（勝手に使われても上限まで） | サーバーに繋いでいない版。中 |
| B | キーをパスキー・合言葉で暗号化して置き、使う時だけ開ける | 使う時に盗まれうる（3.3） | AI の前に指の確認。中 |
| C | Trusted Types で innerHTML を禁止 | 入口を減らす | Firefox 未対応。`el()` の作り直し。中 |
| D | Solana の窓口をサーバー経由に | WebRTC が残る | 大 |
| E | 上限額（運用） | 被害が上限で止まる | どの案とも組む |
| F | キーと送信だけを**別オリジン**の小さな専用ページに置き、本体は postMessage で頼む | 盗まれない（勝手に使われても上限まで） | 別オリジンが要る。iPhone で埋め込みの保存場所が残るか要確認。大きめ |
| G | Android の Keystore に置き、ネイティブから送る | 盗まれない | Capacitor のプラグイン（Java/Kotlin）。中 |
| H | iOS の app に包み Keychain に置く | 盗まれない | Xcode・開発者登録 |
| **I** | **キーを置かず、使う時に毎回入れる**（パスワード管理＝iCloud キーチェーンの自動入力） | 使わない時は何も無い。使う時は盗まれうる | 小。どの版でも同じ |

F の別オリジンの候補（登録・料金なし）:
- GitHub の **Organization** を作り、その Pages（`<組織名>.github.io`。Public Suffix List により別サイト扱い）。組織名は公開される
- サーバーあり版なら同じサーバーの別ポート
- 同じアカウントの別 repo の Pages は**同じオリジンなので不可**

F の注意: 専用ページは iframe の中の「よそのサイトの部品」になる。Safari の「7 日開かないサイトのデータを消す」はホーム画面のアプリには当てはまらないとされるが、その中の他サイトの iframe が例外に入るかは不明 → 実機で確かめる。キーは本体の偽の欄ではなく専用ページの欄に入れる（住所を見せる）。

## 5. 最後のおすすめ（2026-11-12）
1. まず **I（毎回入れる＋パスワード管理）**: 小さく、どの版でも効き、使わない時は何も取られない。
2. サーバーあり版に **A**。
3. 「盗まれない」をサーバーなしでも得たいなら、Android は **G**、iPhone は **F（Organization の Pages）か H**。
4. どの場合も **E（上限額）** と「悪いコードを動かさない」守りは続ける。
