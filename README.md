# Bubbles

思いついたことを書き出して、漂わせておくための todo アプリ（試作）。

**[動かしてみる →](https://rh-rep.github.io/bubbles-todo/)**

---

## このアプリが引き受けないこと

普通の todo アプリは、開くと「やっていないことの山」を返してくる。
これはその形を採らない。**未処理の山を、罰として突き返さない。**

そのために、次のものを**作らない**と決めてある。

- 達成率・パーセント・分母のある数字
- 連続日数（ストリーク）
- 完了したときのご褒美演出
- 「やる気」ゲージのようなもの
- やらなかった日を赤くすること
- 命令形の文言（「〜しなさい」「〜しましょう」）

**時計は出すが、時計は記録に触らない。**残り時間は見えるほうが時間を区切りやすいので出す。
ただし「5分に届いたか」で「はじめた」を立てることはしない——それをやると、
4分でやめた人には何も残らない、分母を書かないだけの達成条件になる。
立てるのは**押したボタン**のほう。

記録するのは **「はじめた」** だけ。**「終わったか」は訊かない。**
（画面のボタンは **「今日は終わり」**。押すとその項目は薄くなり、日付が変わると戻る。
記録として残るのは「手をつけた」という事実のほうで、そこは変わらない。）
「作業メモ → 次の一手」は git のように積み上がるが、**積むのは押したときだけ**
（打っている途中では記録しない）。
完了は、訊かれて答えるものではなく、**自分から押したいときに押すもの**として置いてある。

**完了しても、置いた日の水面からは消えない**（利用者の指示）。消すと
「その日なにを達成したか」が残らないため。残るほうには ✓ が1つ付くだけで、
数も、割合も、祝いの演出も出ない。さいころ（ランダムに1つ選ぶ）は、
✓ の付いたものを引かない。

「消す」は本当に消しているように見えるが、内部では墓石として残る
（表示からは完全に消えるが、記録としては残り続ける）。

## 6つの画面

| | |
|---|---|
| **海** | 思いつきを吐き出す場所。バブルが漂う。**上=長期保留 / 下=完了**（動かせない固有枠）、左右はタグの海。出すのは新しいほうから20件まで。狭い画面では、バブルを 0.8 倍まで縮め、それでも入らなければ数を減らす（面積の合計を海の 45% まで。Issue #2）。残りは「リスト表示」で読む |

長期保留には**もどってくる日**を添えられる。その日が来ると、ほかの海へ静かに戻る
（「期限切れ」も「◯日放置」も出さない。過ぎた日は、開いた時点で戻すだけ）。
| **今日** | 今日やると決めたもの |
| **きっかけ** | 「歯を磨いたら」のような、行動のきっかけにぶら下げるもの |
| **すきま** | 耳だけ空いている／画面が見られる、といった状況ごとの枠。**きっかけと同じ形**で、枠は自分で決める |
| **ふりかえり** | 完了ではなく**着手**の記録。帯グラフは置いていない（比率の絵になるため） |
| **設定** | タグの管理、音（完了音・効果音）のオン/オフ、この端末の表示（起動時の画面・風・タグ類・タブの並び。AI に頼んでも変えられる） |

**期間で長期保留へ回す**（2026-11-12 利用者の決定。共有の記録 v1.5 §11）。泡の欄 `start`・`due`（盤の「期間」、gantt_todo の日付）の**外**にあるものは、
長期保留の海に浮かぶ。期間の**中**にあるものと、期間の無いものは今までどおり基本の海（中央・タグの海）。基本の海が溢れず、今日のうちに見るものが基本に出る。
- 中か外かは、start と due の両方なら start ≦ 今日 ≦ due、start だけなら start ≦ 今日、due だけなら 今日 ≦ due（今日は端末の時刻。境目の日は中）。本文の古い「期間:」の行は見ない
- **表示の決まりで、記録は変えない。**`hold` は書かない（gantt で waiting に見え、端末どうしの書き込みもぶつかるため）。描くたびに今日で決め直すので、日をまたげば出る海も変わる（`store.spanHeld`・`spanHeldItems`、`js/screens/sea.js`）
- 手で長期保留にしたものは期間の中でも長期保留。今日に置いたもの（`days` に今日）は期間の外でも今日に出す。完了は今までどおり下の海
- 長期保留の海では、泡の下の縁に小さく「11/20 から」「期間を過ぎた」と出す（リスト表示・引き出しの長期保留も同じ）。赤にも「期限切れ」の札にもしない
- **基本の海へ出すには**、盤の「期間」を変えるか消す（その場で戻る）。今日に置けば今日に出る。外す枠へ運ぶと、そう案内する（記録の長期保留ではないので、外すものが無い）
- 「日付で見る」はもとからどの海のものも並べるので変わらない。「今日」は `days` だけで決まるので変わらない。今日のおすすめの候補（`js/suggest.js`）も今までどおり

バブルはタブへ直接ドラッグできる。落としても**移動ではなく、状態が増える**
（今日にもあるし、きっかけにもある、という持ち方ができる）。

**左上の ≡ は「引き出し」。**取り出す場所で、「最近つかった」「お気に入り」「長期保留」と、タグごとの区分
（仕事・買い物…）を一覧で見て、1タップで今日の水面に置く。置き場ではなく入口で、
本体はそれぞれ記録・印・上の海・タグにある。区分は見出しで開閉し、**既定で開いているのは「最近つかった」だけ**。
名前を押すと、その泡をふだんタップしたときと同じ盤（編集）が開く。
「今日に」とその取り消し以外は、その盤の仕事。順番だけを出し、回数も日数も出さない。
長期保留を今日に置くと、保留は解ける（トーストの「取り消す」で戻る）。
お気に入りは、バブルの盤の ☆ で付け外しする（タグではないので、海にも色にもならない）。

## 触り方

- **タップ** … バブルが中央に来る。次の一手・リンク・履歴・タグの付け外しが出る
- **バブルの [OK]** … いつの日・次の一手・リンクを書き留める
- **バブルの [作業メモ]** … 別の面が開く。[作業メモを保存] で「作業メモ → 次の一手」を1組にして、git のように記録を積む
- **[履歴]** … 積んだ記録を日時つきで古い順に読む（バブルの盤からも、5分の集中画面からも）
- **中央の [タスク開始]** … 5分の集中画面へ。**残り時間の数字と輪が出る。**
  過ぎたら止まらずにカウントアップへ切り替わる（「あと5分？」とは聞かない）。
  そこでも同じ組を積める
- **タブへドラッグ** … その状態を足す
- **今日の画面を左右になぞる／‹ ›** … 前の日・次の日へ
- **盤のカレンダー** … その項目を置く日を、押して入り切りする（複数の日に置ける）
- **海の端へドラッグ** … そのタグが付く
- **左上の ≡（引き出し）** … 最近つかった／お気に入り／長期保留／タグごと から、今日の水面に置く。名前を押すと盤が開く
- **盤の ☆** … お気に入りの印を付け外しする
- **盤の「名前」** … 名前を書き直す。閉じると反映される。空にはできない。過去の記録に残る名前は当時のまま
- **盤の「本文」**（Issue #8）… 名前とは別の、変わらない説明（何を・どこで・気をつけること）。入口を押すと別の面で開き、閉じると残る。本文があるときは、まず読むだけの大きな面（画面の上から下タブの手前まで。キーボードは出ない）で開き、見出しの [編集] で書く面に変わる。本文がまだ無いときは、すぐ書く面で開く（Issue #16）。書く面の見出しは [キャンセル]（書く面に入る前の本文へ戻して閉じる）と [保存]。外を触る・Escape でも残る（Issue #35）。書くのは任意で、海の入力欄には足さない。作業メモと違い、履歴には積まない（書き替えるもの）
- **矢印看板を押す／背景をなぞる** … となりの海へ
- **引いて見る** … バブルを小さくして、一度に多く見る
- **リスト表示** … 書いたものを古い順に、文字の一覧で読む（海に出ていないぶんもここに）
- **しぼる** … 中央の海を、タグごとに絞る（長期保留もここから呼べる）

## 改善のコメント（右上の !）

右上の隅の小さな **!** を押すと、改善のコメントを書く欄が開く。「GitHub を開く」で、
この repo（RH-REP/bubbles-todo）の**新しい Issue の画面が、画面 ID（`sea`・`board`・`focus` など）とコメントを書き込んだ状態で開く**。
送るのは GitHub の画面で「Create」を押したとき（GitHub のログインが要る）。この app 自身は送らない。

- **repo は公開**なので、送った中身は誰でも読める。バブルの文字が写るので、**画面の写真は初めは付けない**（チェックを入れたときだけ付く。付けるときは中身に注意）。画面のエラーなどの記録の欄は出さない
- **書いたもの（バブルの本文）は送らない。**「今の状態」として付くのは、開いている画面と件数（海・今日・長期保留・完了・タグ）だけ
- 部品は `js/feedback.js`（issue_hub の正本をそのまま写したもの。直すなら正本を直して写し直す）。画面 ID は各画面・板に付けた `data-screen` から読む
- 「!」は右上の隅に、歯車と同じ 44px の丸で置いてある。歯車はその左どなり、海のカレンダーはさらに左（`css/base.css`）
- **iPhone に GitHub アプリが入っていると、「GitHub を開く」が Issue の画面を空欄のまま開くことがある**（iOS の Universal Links が `github.com` のリンクを横取りしてアプリを開くため。OS の仕組みで、app 側からは止められない。Issue #5）。
  備えとして、押した時点で**題名とコメントをクリップボードにも置く**ので、空欄で開いたときはそこへ貼り付けられる。
  クリップボードの文は「題名、空行、コメント」だけ（画面・版・時刻などの付記は入れない）。題名は `[画面ID] ` と、題名の欄に書いたもの（空ならコメントの最初の1文。長ければ 50 字で切る）
- **題名の欄と「AI で題名」（2026-11-07。利用者の指示 Issue #10）**: コメントの下に題名の欄がある。空のままなら、今までどおりコメントの最初の1文が題名になる（欄に薄く見せる）。
  横の **[AI で題名]** を押すと、コメントの文から 15〜30 字ほど（40 字まで）の題名の案を AI に作らせ、欄に入れる。直してから「GitHub を開く」を押す。
  返事を待ってから GitHub を開くと iPhone の Safari がポップアップとして止めるので、作るのと開くのは別の操作にしてある。
  **送るのは押したときのコメントの文だけ**（画面 ID・件数・写真・泡の中身は送らない。欄の下にそう出す）。キーが無ければ送らずに「設定の『AI を使う設定をする』に入れると使える」と出す。
  開いたときや打っている間に自動では作らない。作り: `js/feedback.js` の差し込み口 `makeTitle`（渡した app だけボタンが出る）、`js/app.js` の `AppFeedback.install`、`js/research.js` の `buildIssueTitlePrompt`・`cleanIssueTitle`。
  **issue_hub の正本（`feedback/feedback.js`）にはまだ戻していない**（#5 のクリップボードの分も同じく、写しだけが先に進んでいる）
  ブラウザで開きたいときは、GitHub アプリ側でリンクを長押しして「開く」を選べば、次回からその種のリンクは Safari で開く（iOS の設定。app 側の機能ではない）

## AI に訊く（ヘルプ。2026-11-04。利用者の指示 Issue #9）

設定の「ヘルプを開く」（使い方を読むの下の1行。2026-11-11 Issue #45 で AI の箱から分けた）から、使い方や不具合っぽい動きを AI（Anthropic・Claude）に尋ねられる。

- **キー**: 設定の「AI を使う設定をする」に API キーの欄がある。入っていれば「入っている（…末尾4字）」と「変える」「消す」だけを出し、
  入っていないときだけ入力欄（Enter でも保存）。欄の上に「何を入れるか・何に使うか」と Console のキーの頁へのリンクをいつも見える字で出す（Issue #45）。Anthropic Console で発行したキーを入れる。ヘルプ・先の予定・本文の面の AI（下）で使う。
  キーは端末の `localStorage`（`bubble_todo_ai_key`）にだけ置く。**サーバーへは送らない**
  （CSV の書き出し・サーバー同期・改善のコメント・エラーの記録のどれにも混ざらない。
  保存の箱と CSV は `tests/ai.test.mjs`、同期・改善のコメント・エラーの記録・引っ越しのファイルは `tests/key-leak.test.mjs`）。
  引っ越しのファイル（Issue #19）にもキーは入れない。新しい端末では入れ直す
- **HTML として描かない（Issue #14）**: キーを読み出せるのは、ページの中で動くスクリプトだけ。利用者・共同の海のほかの人・AI が書いた文字
  （名前・本文・ひとこと・タグ名・AI の返事）は `textContent` で描き、`js/ui.js` の `el()` の第3引数（innerHTML）には入れない。
  `tests/html-sink.test.mjs` が `el(` の第3引数にデータの欄（`.text` `.name` `.by` など）が入っていないかを見る
- **モデル（2026-11-05 追加。Issue #13）**: 既定は `claude-opus-5-5`（Opus 5.5。2026-11-07 利用者の指示。前は Haiku 5.5）。設定の「AI を使う設定をする」の
  「AI のモデル」で Sonnet 5.5・Haiku 5.5（速い・安い）に変えられる（ヘルプ・先の予定・本文の AI のすべてに効く。上ほど賢いが 1 回の料金も上がる）。
  選びは端末の `localStorage`（`bubble_todo_ai_model`）にだけ置く。同期・CSV には乗らない
- **発行のしかた（利用者の運用。Issue #14）**: このキーは暗号化しても「端末の中で悪いコードが動く」場合は守れない
  （呼ぶときにこの app 自身が平文へ戻して使うため）。代わりに、漏れたときの被害を小さくする:
  - Anthropic Console で、この app 専用のワークスペースを作り、そこで発行したキーを使う（ほかの用途と上限額を分ける）
  - そのワークスペースに**使える上限額**を決めておく（漏れても被害がそこで止まる）
  - キー単位の有効期限が無い場合は、自分で定期的にキーを作り直し、古いキーを Console から取り消す
  - 使わないときは設定の「消す」でこの端末から消す
- **送り先**: ブラウザから Anthropic の API（`api.anthropic.com`）へ直接。server.py を介さない
  （`anthropic-dangerous-direct-browser-access` ヘッダを付けて呼ぶ。鍵は使う人が自分の端末に置く前提の、Anthropic 自身の仕組み）
- **AI の会社を選ぶ（2026-11-12 Issue #46 の A 案）**: 設定の「AI を使う設定をする」の「AI の会社」で、
  Anthropic（Claude）・OpenAI（GPT。`api.openai.com` の chat/completions、`Authorization: Bearer`）・
  Google Gemini（`generativelanguage.googleapis.com` の generateContent、`x-goog-api-key`）から 1 社を選ぶ。
  選べるのは `js/ai.js` の `PROVIDERS` の 3 社だけで、その窓口を CSP の connect-src に決め打ちで書いた
  （`tests/chain.test.mjs` が `PROVIDERS` と CSP を突き合わせる）。住所を自分で入れる形（OpenAI 互換の任意の住所）は、CSP を広げることになるので作らない。
  - キーは会社ごとに別の箱（`bubble_todo_ai_key`＝Anthropic、`bubble_todo_ai_key_openai`、`bubble_todo_ai_key_gemini`）。
    切り替えてもほかの会社のキーは消えない。どれも `bubble_todo_ai_key` で始まり、版を戻すときの写し（`js/rollback.js`）にも入らない
  - モデルも会社ごとに覚える（`bubble_todo_ai_model`・`_openai`・`_gemini`）。一覧に無い新しいモデルは「手で入れる」で名前を入れる
    （英数字と `. _ : -` だけ。`custom:<名前>` で保存）
  - どの会社でも、各機能が送る中身は同じ（下の「作り」の例外のとおり）
  - **Web で調べるもの（先の予定・本文の「AI で調べる」「AI に訊く」）は Anthropic のときだけ**（Anthropic の Web 検索ツールを使うため）。
    ほかの会社では理由を出して断る（`canSearch()`）
  - OpenAI の GPT-5 系・Gemini 2.5 系は考える分も出力の上限に数えるので、この 2 社には上限を 8000 以上で渡す（使った分だけ課金）
- **ページの守り（CSP）の今の形**（Issue #14 の見直し、2026-11-11）:

  | 開き方 | CSP | よそのスクリプトを動かさない（script-src 'self'） | 送り先の決め打ち（connect-src） |
  |---|---|---|---|
  | server.py が配るページ | ヘッダー（server.py の `CSP`） | ある | `'self'`・Anthropic・OpenAI・Gemini・天気・Solana の公式 RPC |
  | solo.html（GitHub Pages・Android でサーバーに繋いでいないとき。js/boot-edition.js が移す） | `<meta>` | ある | 同上 |
  | index.html を GitHub Pages・Android で開き、サーバーに繋いでいるとき | `<meta>`（2026-11-11 に足した） | ある | **無い**（`*`。利用者が入れる同期の住所に繋ぐため） |

  - **送り先の決め打ちは、キーを外へ出さない柵としてはもう完全ではない。**Solana の公式 RPC は誰でも書ける公開の掲示板なので、
    ページの中で悪いコードが動けば、自分で持ち込んだウォレットでキーをチェーンに書き出せる。WebRTC（js/p2p.js）は CSP の connect-src の
    対象外で、どのページでも塞げない。だから守りの主は「悪いコードを動かさない」こと:
    外のスクリプトを読まない（外部依存ゼロ）・`script-src 'self'`（差し込まれた `<script>` や `onclick=` を動かさない）・
    人や AI の文字を HTML にしない（上の「HTML として描かない」）。index.html の `<meta>` はこのために足した（connect-src は開けたまま）
  - index.html の `<meta>` は solo.html の `<meta>` と同じ位置に置く（tests/chain.test.mjs が両方の CSP の行を外して見比べる）。
    server.py が配るときはヘッダーと `<meta>` の両方が効き、厳しいほう（ヘッダーの connect-src）になる
- **送る中身**: 書いた質問の文・この app の使い方の要約（README の目次ぶん）・版と今の画面 ID・件数（海・今日・長期保留・完了・タグ）だけ。
  **バブルの本文・作業メモは送らない**
- **画面**（2026-11-04 UI 見直し）: 見出し／流れる中身／下に留まる入力欄の3段。入力欄は会話が伸びても画面の外へ出ない。
  - 上に使い方の記事（`docs/guide/`）の目次（2列・畳める。会話を始めると畳む）、その下に例の質問（押すとそのまま訊く）
  - 待っている間は3つの点。返事の Markdown の飾り（`**`・`#`・行頭の `-`）は落として素の文で出す（HTML としては扱わない）
  - 届かなかったときは理由と「もう一度送る」。届かなかった質問は会話の続きに入れない
  - 入力欄は中身に合わせて5行まで伸びる。⌘/Ctrl+Enter で送る。開いた直後は入力欄に焦点を置かない（スマホでキーボードが目次を隠すため）
  - 会話は**端末のメモリにだけ**置き、閉じると消える（保存しない）。端末の「戻る」でも閉じる
  - 返事が来てから「この会話から改善の Issue を書く」が出る（右上の **!** と同じ仕組みで要約を書き込んだ状態で開く）

## 海域（サーバーで記録を共有する）

自分で立てたサーバーに記録を置き、複数の端末（Mac・スマホ・Android 版）から同じ記録を使う。

**海域**（2026-11-10 利用者の決定）: 1つのサーバーが預かる海のまとまり（個人・共有・作った海）。画面では、入る・記録を送る・持ち主のときは「海域」、住所・コマンド・サーバーのプログラムのときは「サーバー」と呼ぶ。海域はサーバーを1台立てるとでき、海域の中の海は端末の引き出しで作る。

- **サーバー**: `python3 server.py`（Python の標準ライブラリだけ）。app 本体も一緒に配る。
  - 記録は `<データの場所>/state.json` 1つ。書くたびに前の版を `backup/` に残す（新しいほうから50個）
  - データの場所は `--data-dir` → 環境変数 `BUBBLE_TODO_DATA` → このフォルダの `data/`（`.gitignore` 済み）
  - 合言葉は環境変数 `BUBBLE_TODO_TOKEN` → `<データの場所>/token.txt`。無ければ初回に作って画面に出す
  - 既定では `127.0.0.1` だけで待ち受ける（外へは前段の Caddy で出す。下の「公開して使う」）
  - 配るのは `index.html`・`manifest.json`・`sw.js`・`css/`・`js/`・`icons/` だけ。`.git`・`.env`・`data/` は出さない
- **端末**: 設定の「サーバー」に住所を入れる。サーバーがパスキーの形（公開したサーバー）なら招待コードで登録するか、端末から「登録を頼む」（持ち主がサーバーで認める）。合言葉の形（手元の Mac の `start.command`）なら合言葉を入れて「繋ぐ」。server.py が配っているページなら「このページのサーバー」で住所が入る。
  「繋がない」で切ると、記録はその端末に残ったまま、送らなくなる。
- **合わせ方**: 記録（todo・アンカー・タグ・着手ログ…）ごとに、最後に書き換えた時刻を持つ。食い違ったら**新しく書き換えたほうが残る**
  （利用者の指示）。消したものも「消した時刻」で比べるので、片方で消したものが戻ってこない。
  サーバーに届かない間も、端末にはふだんどおり記録され、届いたら合わせる。
  - 合わせる計算は端末の側（`js/merge.js`）。サーバーは版つきで JSON を1つ預かるだけで、版が違う書き込みは 409 で断る（端末が取り直す）
  - 時刻は端末の時計。時計が大きくずれた端末の書き換えは、新しくても負けることがある
  - 日の切り替え（はじめた記録が消える）は「その日の0時」の時刻で付ける。あとから開いた端末の切り替えが、今日ほかの端末で付けたはじめたを消さないため
  - 印を持たない前の版の記録は、最初に開いたときに「前からの記録」の印（1）を付けて引き継ぐ。新しい端末の空の既定値（0）には負けない
- **ほかの app と共有する欄（共有の記録 v1.1。2026-11-10）**: サーバーの記録は gantt_todo・diary も読む（gantt は書く）。
  todo の `start`・`due`（`YYYY-MM-DD`。**期間の正本**）・`project`（ふつうのタグの id。特別なタグは入れない）・`ext`（app ごとの持ち物。中は見ない）
  を形を確かめて残す（`js/store.js` の `sharedFields`。形の違う値と null・空は欄ごと省く）。
  **知らない欄は丸ごと残す**：todo の知らない欄（`normalizeTodo` の `TODO_KNOWN` に無いもの）、保存データの頂上の知らない欄（`docOf()` の `docExtra`）、
  サーバーの `data` の頂上（`doc`・`stamps` の横）の知らない欄（`js/sync.js` が PUT に載せ直す）。
  形の決まりはこの repo の外の仕様書（共有の記録 v1.1）が正。テスト: `node tests/shared-fields.test.mjs`・`node tests/schema.test.mjs`
- **記録の形の版（2026-11-10。共有の記録 v1.1 §6。利用者の指示「非互換性 update を通知するための機能」）**:
  古い版の端末は、新しい欄を知らずに落とし、印が変わらないまま広げてしまう
  （`library/tech_stack/difficulty_log/20261110_old_client_strips_new_fields_lww.md`）。そこで版で守る。
  - 端末は分かる記録の形の版 `SCHEMA`（`js/sync.js`。いま `1`）を、すべての要求に頭書き `X-Bubbles-Schema` で付ける
  - サーバーは受け付ける最も古い版を `--min-schema`（環境変数 `BUBBLE_TODO_MIN_SCHEMA`。既定 `1`）で持ち、`GET /api/data` の応答に `minSchema` を足す。
    `PUT /api/data` で頭書きが無いか `minSchema` より小さければ、書かずに `426 {"error":"upgrade","minSchema":n}`（個人・共有・作った海のどれでも）。GET は断らない
  - 端末は GET の `minSchema` が `SCHEMA` より大きいか、PUT が 426 なら、同期を止めて（合わせない・書かない）状態を `outdated` にし、
    画面の上に帯「この版は古いので同期を止めた。更新すると続きから合わさる」と **[今すぐ更新]** を出す（`js/schemaguard.js`。
    `js/update.js` の `checkForUpdate` → `applyUpdate`。新しい版が見つからなければそう出す）。手元の変更は印つきで残り、入れ替わったあとの同期で入る
    - 押したあとの字は端末で分ける：Android の app（`window.Capacitor`）は確かめに行かず「app を作り直して入れ直す」、
      service worker の登録が無いブラウザは「ページを読み直す」（ボタンが [読み直す] になる）、登録はあるが新しい版がまだ無ければ「まだ見つからない」
    - 帯が出ている間は、帯の高さを `--guard-h` に入れて `html.has-guard` を付け、`--safe-t` に足す。上の段（海の帯・≡・歯車・!）がそろって帯の下へ下がり、海の切り替えも押せる
  - **互換性の無い変更を入れる手順**（古い版が読み書きすると記録が壊れる変更）:
    1. `js/sync.js` の `SCHEMA` を1つ上げ、その変更を入れた版を作る（`sw.js` と `js/version.js` の版も上げる）
    2. 新しい版を**先に配る**（サーバーの `update.command`。PWA は次に開いたとき、または帯・設定の [今すぐ更新] で入れ替わる）
    3. Android の app（Capacitor。`www/` を中に同梱）は**自動では入れ替わらない**。`npm run android:build` で作り直して入れ直す
    4. 配り終えてから、サーバーを `--min-schema <新しい版>` で起動し直す。まだ古い端末は 426 で止まり、帯で更新を求められる（記録は消えない）
    5. 同じ記録を読み書きする gantt_todo・diary も、同じ版を送るように直す（仕様書 §6）
  - v1.1 より前の bubble は 426 を知らないので、同期の欄に「サーバーに書けなかった（426）」と出るだけになる（記録は消えない）
  - よそのオリジン（Android 版）から呼ぶので、`X-Bubbles-Schema` は CORS の `Access-Control-Allow-Headers` にも入れてある。
    **サーバーを先に新しくする**こと（前の版のサーバーは、この頭書きを付けた Android 版の要求を CORS で断る）
- **Android エミュレーターから Mac のサーバーに繋ぐ（開発用）**: `adb reverse tcp:8931 tcp:8931` をしてから、アプリの設定で住所に `http://localhost:8931` を入れる
  （2026-10-23 に、エミュレーターのアプリとブラウザの web 版で同じ記録になるのを確かめた）。
  - `http://10.0.2.2:8931`（エミュレーターから見た Mac）は使えない。アプリのページは `https://localhost` なので、http の住所は混在コンテンツとして止められる
  - Android は http を既定で断るので、`tools/patch-android.mjs`（`npm run sync` の最後で走る）が `localhost` と `127.0.0.1` にだけ http を許す設定を足す
  - Android 版の設定には「このページのサーバー」を出さない（ページの住所はサーバーではないため）
  - まだ確かめていない: 実機の Android
- 2026-10-25 に、合言葉で入って Tailscale の `tailscale serve` で tailnet にだけ見せる形（Tailscale 版）は外した（利用者の指示）。
  外した理由: 招く人ごとにアプリとアカウントが要り、スマホのほかの VPN とぶつかるため。公開してパスキーで入る形（下）に替えた。
  手順と考え方は my_knowledge の技術スタックに残し、例のコードはこの repo の履歴（commit `0263e6a` まで）にある。

## 公開して使う（パスキー。2026-10-24 に作り、2026-10-25 に main へ取り込んだ）

サーバーをインターネットに公開して使う形（サーバーに置くときは、この形だけ）。
入場はパスキーだけ（合言葉では入れない）。サーバーが世界から見えることは受け入れ、そのうえで入場・負荷・乗っ取りの道を絞る。

- **入場（パスキー）**: 持ち主がサーバーで招待コード（1回きり・24時間）を作り、端末は設定の「パスキー」で登録する。
  端末が作った鍵の組のうち、公開鍵だけがサーバーへ行く（秘密の鍵は端末から出ない。Face ID・指紋・PIN で守られる）。
  以後は「パスキーで入る」で、通行証（30日）を受け取って合わせる。端末ごとに `passkey-remove <名前>` で取り消せる（次の要求から入れない）
  - 招待は置き場つき: `invite-add <名前> me:1,share`（自分の端末）／`invite-add <名前> me,share`（招く人。その人だけの個人を作る）／`invite-add <名前> share`（招く人。個人は無し）
  - **端末から先に頼む**（2026-11-07 Issue #26。サーバーの操作を先にしなくてよい）: 端末の設定の「パスキー」で呼び名を入れて「登録を頼む」。
    画面に確かめの字（例 `ABC-DEF`）が出るので、持ち主に伝える。持ち主はサーバーで `request-list` を見て、同じ字を
    `request-ok <字> --space …`（置き場は `invite-add` と同じ書き方）で認める（断るなら `request-no <字>`）。
    端末は 8 秒ごとに様子を聞き（「様子を見る」でもよい）、認められたら「登録を仕上げる」でパスキーを作る。
    - `tools/server-setup.sh` で立てたサーバーでは、同じことを `bash bubbles-todo/tools/server-setup.sh request-list`・`request-ok <字> <置き場>`・`request-no <字>` で打てる
      （`limit`・`limit-set <数>` も。2026-11-07 Issue #25 の返事で足した）。使うには、サーバーが版 2026-11-07o 以降であること（`server-setup.sh update`）
    - 送るのは呼び名（40 字まで）だけ。サーバーは字・呼び名・端末の鍵の sha256・接続元の sha256 の頭を `requests.json`（600）に 24 時間置く。
      認めると、端末の鍵がそのまま招待コード（`invites.json` の `kind: 'request'`、24 時間・1回きり）になる
    - 待たせられる頼みは全体で 10、1つの接続元から 3 まで（溢れたら 429 `requests`）。字は秘密ではないので、
      持ち主は**端末の画面の字と呼び名が合うものだけ**を認める
    - 端末は頼みを `bubble_todo_pk_request` に置き、設定を開き直すと続きから。登録した・やめたら消す
  - **個人は人ごと**（2026-11-03 利用者の指示）: 人はサーバーに登録した順の番号で分ける。`me` は新しい番号の人、`me:<番号>` はその人の2台目。
    1 番はサーバーを立てた人（持ち主）で、記録は `state.json` のまま。ほかの人は `people/<番号>/state.json`。ほかの人の個人は読めない。
    番号の無い前の版のパスキーは 1 番。ほかの人の端末を前の版で `me` に入れていたら、`passkey-person <名前> new`（または `<番号>`）で移す。
    移された端末は、次に合わせたとき手元の個人をサーバーのものへ入れ替え、前の中身を `bubble_todo_v1_before_person_<時刻>` に残す（`js/sync.js`）
  - サーバーに置くのは公開鍵・招待コードの sha256・通行証の sha256 だけ（`passkeys.json`・`invites.json`・`sessions.json`。600）
  - 確かめ（`passkey_crypto.py`）: ES256・RS256。`cryptography` があれば使い、無ければ標準ライブラリだけで計算する。
    名前（rp id）・出どころ（origin）・問題（1回きり・5分）・本人の確かめ（UV）・署名の回数（戻ったら断る）を見る
  - 名前の住所（`https://<名前>`）が要る。IP の住所ではパスキーを使えない。名前を変えると登録し直し
  - **数の上限**（2026-10-24 利用者の指示）: 登録できるパスキーは置き場ごとに 3 つ（個人と海の両方に入れる端末は両方に数える。いっぱいなら招待コードも作らず、登録も 409 で断る）。
    同時に使える端末は 3 台（30分以内に記録を読み書きした端末を数える。4台目は 429 `devices`、端末には「使っている端末が多い」と出す。出た端末はすぐ外す）。
    `--max-passkeys`・`--max-devices`・`--device-window`（環境変数 `BUBBLE_TODO_MAX_PASSKEYS` など）で変えられる。
    **登録の上限はあとからも変えられる**（2026-11-07 Issue #26）: `python3 server.py limit-set <数>`（1〜100。`limit` で今の値）。
    `<データの場所>/limits.json` に書き、動いているサーバーにも止めずに次の要求から効く（`--max-passkeys` より先）。
    下げても登録済みのパスキーは外さず、上限より少なくなるまで新しい登録を断る（どこが多いかは `limit-set` のときに出す）
- **機械の鍵**（2026-11-11。共有の記録 v1.2 §8）: gantt_todo・diary・秘書（todo_secretary）など、パスキーを持てない機械が
  公開の形のサーバーの記録を読み書きするための鍵。合言葉の形（`--auth token`）では使わない（今までどおり `token.txt`）。
  - 作る・見る・消すのはサーバーの持ち主だけ（サーバーの機械で。動いているサーバーは止めなくてよい。次の要求から効く）:
    ```bash
    python3 server.py --data-dir <データの場所> machine-add gantt --space me              # 持ち主の個人。読み書き
    python3 server.py --data-dir <データの場所> machine-add diary --space me --read-only  # 読むだけ
    python3 server.py --data-dir <データの場所> machine-add 秘書 --space me:2              # 2 番の人の個人
    python3 server.py --data-dir <データの場所> machine-list
    python3 server.py --data-dir <データの場所> machine-remove diary
    ```
  - 鍵（`bm_…`）は `machine-add` のときに**1度だけ**出る。サーバーには sha256 だけを残す（`<データの場所>/machine_keys.json`、600）。失くしたら消して作り直す
  - 効くのは `GET`・`PUT /api/data` だけ。`Authorization: Bearer <鍵>`、`X-Bubbles-Schema: 1`。置き場は鍵に決めた個人1つで、
    `X-Bubbles-Space` は省くか `me`（ほかを言えば 403）。読むだけの鍵の `PUT` は 403。海の一覧・パスキー・招待などほかの API には効かない（401）
  - 応答は端末と同じ形（`{space, version, data, minSchema}`）に、`person`（誰の個人か）と `owner: false` が付く。`PUT` の 409・426 も端末と同じ
  - 端末の数（`--max-devices`）には数えない。入場の失敗・要求数の守りは端末と同じに効く（違う鍵が続けば 429）。
    記録（journal）には `machine-forbidden name=<名前> …` の形で名前だけを出し、鍵は出さない。fail2ban は正しい鍵の 403 を数えない
  - Origin を付けないサーバー同士の要求で通る（CORS は要らない）
  - **gantt・diary・秘書に渡す手順**: 鍵をその機械のファイルに入れて、所有者だけが読めるようにする（`chmod 600`）。
    gantt・diary は `--bubble-token-file <そのファイル>` と、サーバーの住所（`https://<名前>`）で起動する。秘書は設定の `key_file` にそのファイルを書く。
    鍵の中身は画面・ログ・会話に出さない。diary には `--read-only` の鍵、gantt と秘書には読み書きの鍵を渡す
- **守り**（`guard.py`・`server.py`。合言葉の形でも効く）:
  - 接続元ごとの同時接続 8・全体 64（超えたら読まずに 429）、要求 120 回/分、入場の失敗 10 回/10分（超えたら 429）
  - 1つの接続の待ちは 15 秒、受け取る大きさは 4MB まで
  - 配るページに CSP（`script-src 'self'` など）・`nosniff`・`X-Frame-Options: DENY`・`no-referrer`。直書きのスクリプトをやめた（`js/boot-dvh.js`・`js/sw-register.js`）
  - よそのオリジンから呼んでよい相手は決めたものだけ（合言葉の形は Android 版だけ、公開の形は無し）。サーバーの版を名乗らない
  - 守りの出来事を `bubbles: auth-fail ip=…` の形で標準エラーに出す（値は出さない）。fail2ban が読んで締め出す
- **前段（Caddy）**: HTTPS の証明書・待ち時間・大きさの上限（`tools/public/Caddyfile.template`）。server.py は 127.0.0.1 のまま、`--trust-proxy` で接続元を数える
- **立ち上げ**: `BUBBLES_DOMAIN=<名前> bash tools/server-setup.sh`（名前は `<データの場所>/.setup` に覚え、`update` は環境変数なしでよい）。前の Tailscale 版で立ち上げた置き場では、名前を付けるよう言って止まる。
  Caddy と fail2ban は入っていれば設定を置く。ファイアウォール（クラウドとサーバーの中）で 80・443 を開ける手順は画面に出す（自動では開けない）
- **テスト**: `python3 -m unittest tests/test_passkey_crypto.py tests/test_server_public.py tests/test_server_machine.py`（署名は Node の暗号の部品で作り突き合わせる）、
  `node tests/passkey-sync.test.mjs`、`node tests/person-sync.test.mjs`（個人を人ごとに分けたときの入れ替え）、`node tests/e2e-passkey.mjs`（headless の Chrome と、Chrome の仮のパスキーで、登録・合わせる・入り直す）、
  `bash tests/server-setup.test.sh`（公開の形を含む）
- **まだ確かめていない**: 本物の公開サーバー・ドメイン・Caddy・fail2ban・本物の端末（Face ID・指紋）。Android の APK では使えない（ページの住所が `https://localhost`）

### 取り消しの積み重ね（⌘Z／Ctrl+Z。2026-11-07。Issue #22）

取り消し付きのトースト（「取り消す」「元に戻す」）は数秒で消え、戻せるのはいちばん新しい1つだけだった。
いまは**トーストを出した操作1つを1つの塊**として控え、トーストが消えたあとも、キーボードの ⌘Z（Windows・Android のキーボードでは Ctrl+Z）で**新しいほうから順に**戻せる。

- 塊の単位: 画面が取り消し付きのトーストを出した操作1つ（完了・消す・今日に置く・タグを付ける／外す・海へ戻す・日を動かす・全部消す など）。戻す手順は各画面がトーストに渡しているものをそのまま使う
- 控えるのは 20 個まで・10分以内。トーストのボタンで戻したものは外す（二重に戻さない）。海を替えると読み直すので消える
- 字を打つ欄（名前・本文）の中では見送り、ブラウザの文字の取り消しに任せる。やり直し（⇧⌘Z）は作らない。読むだけの間は戻さない
- 戻したら「戻した：…（あと N つ戻せる）」と出る。取り消しでないボタンのトースト（「ぜんぶ見る」）は `undo: false` で積み重ねに入れない
- 作り: `js/undo.js`（計算）、`js/ui.js` の `toast`・`undoLast`、`js/app.js` の keydown。テスト: `node --test tests/undo.test.mjs`
- 指だけの端末（キーボードの無いスマホ）では、今までどおりトーストのボタンだけ

### 似ている泡を近くに寄せる（2026-11-07。Issue #23）

海と今日の漂う面で、**似ている泡どうしがゆっくり互いに近づく**。束ねる・まとめるはせず、記録には何も書かない（紐付けの欄は持たない）。
同じようなものが近くに浮いているので、1つを見たときに隣の似たものに気づける、という形にした。

- 似ているの決め方（端末の中だけで計算し、どこへも送らない）: 名前の2文字ずつの組の重なり（Dice 係数）と、同じタグ。
  ひらがなだけの組（「する」「を」など）は数えない（送りがなだけで似ていることにしない）。
  その面の泡すべてに付いているタグは数えない（タグの海は全部が同じタグなので、数えると全部が1つに固まる）
- 寄せ方: 1つの泡が引かれる相手は、似ているほうから2つまで。近づく速さは 8px/s まで（漂う速さの半分）、隙間が 18px より狭ければ引かない。
  ぶつかり・重力・漂いのゆらぎはそのまま効くので、くっつかず近くに居るだけになる。掴んでいる・升目にはまっている泡は動かさない
- 設定の音の節の下「似ている泡を近くに寄せる」で切れる（既定オン。端末にだけ置く `bubble_todo_affinity_v1`）。「視差効果を減らす」のときは漂いが止まるので寄せもしない
- やっていないこと: 手で泡どうしを紐付ける欄（タグで足りるため。記録の形と同期が変わる）、AI で関わりを見つけること（泡の名前を外へ送ることになるため）
- 作り: `js/related.js`（似ている度合いと寄せる力。DOM・保存を触らない）、`js/drift.js`（`setItems` で組を数え、`tick` で `pullStep`）、`js/screens/settings.js`。テスト: `node --test tests/related.test.mjs`

### 海のチャット（サーバーあり版。2026-11-11 Issue #42。#37 の作る順の 3）

### 前の版に戻す（2026-11-07。Issue #21）

新しい版に不具合があったり重くなったりしたとき、**その端末だけ1つ前の版**に戻して使い続けられる。
設定の「前の版（v…）に戻す」で戻し、戻している間は画面の上に帯（「前の版 v… を使っている」）が出る。帯の「最新に戻る」で戻る。
次の新しい版が届いたとき（直した版が入ったとき）も、自動で最新に戻る。

- 戻せるのは**1つ前の版だけ**。`sw.js` は新しい版が入るとき、それまでの版の箱を1つだけ消さずに残す（2つ前より古い箱は消す）。
  この仕組みが入った版（2026-11-07b）より前の箱は、入れ替わったときに消えているので、最初に戻せるのは 2026-11-07b が入る前の版（2026-11-07a）から
- 前の版の箱から出すのは同じ住所の中だけ（`index.html`・`css/`・`js/`・`icons/`）。`sw.js` は戻さない（いつも最新の `sw.js` が前の版の箱から出す）
- **記録を守る決めごと**: 前の版のコードは、新しい版で足した欄を知らず、読み込むときに落として保存する（`js/store.js` の `normalizeTodo` など）。そこで
  1. 戻す前に、端末の記録（`localStorage` の `bubble_todo…`。API キーは除く）の写しを `bubble_todo_rollback_snapshot_v1` に取る
  2. 戻している間は、サーバーへの書き込み（`/api/` への GET 以外。よそのオリジンのサーバーも）を `sw.js` が 503 で止める。前の版の同期は「送れない」になる。欄を落とした記録をほかの端末へ広げないため
  3. 最新に戻って立ち上がったとき（`index.html` の head の `js/rollback.js`。`store.js` が読む前）、写しにあって今の記録に無い欄だけを埋め戻し、写しを消す。戻している間に書いた変更・足した泡・消した泡はそのまま
- 作り: `js/rollback.js`（計算と画面の側。`sw.js` も `importScripts` で読む）、`js/screens/settings.js` の `rollbackBox`、`sw.js`（`activate`・`fetch`）。戻している印は箱 `bubbles-meta` の `__rollback_pin`
- 取り出しは今の版の箱だけから引く（前は `caches.match` ですべての箱を探していた。前の箱を残すと古いファイルが混ざるため変えた）
- テスト: `node --test tests/rollback.test.mjs`（`sw.js` を偽の caches・fetch の上で動かし、箱の残し方・戻している間の出し方・書き込みの停止・印の外れ方を見る）
- service worker の無い環境（`file://`・登録できないブラウザ）と、前の版の箱がまだ無い端末では、設定にそう出るだけ
- まだ確かめていない: 本物の端末（iPhone のホーム画面アプリ・Android の APK）で戻して戻る一巡

## 引っ越し（CSV の書き出し・読み込み）

設定の「書き出し・読み込み（CSV）」（2026-10-24。利用者の指示）。いま開いている海の記録を、まるごと1つの CSV にする（ファイル名と meta の行に海の名前）。
- 形は1行1件（`kind,id,text,date,data,stamp`）。kind と id は合わせる仕組みの記録の鍵（`js/merge.js`）を分けたもの、data は記録の中身の JSON（読み込みの正本）、text と date は人が見るための欄。先頭の meta の行に形の名前と版を入れる。BOM と `\r\n` で、Excel で開いても化けない
- 読み込むときに選ぶ: 「足す」（CSV にしかない記録だけを足す。この端末で消した記録は戻さない。何度読んでも増えない）／「同じものは上書き」（同じ記録を CSV の中身で書き換え、無いものは足す。この端末にしかない記録は残す）
- 読み込んだ記録には今の印を付けるので、サーバーに繋いでいればほかの端末にも届く。招かれた海が読むだけの間は読み込まない
- 書き出し（Issue #7）: 指で触る端末（iPhone・Android）では共有シートでファイルを渡す（「"ファイル"に保存」）。iPhone のホーム画面アプリは `<a download>` でファイルにならないことがあるため。パソコンはふつうのダウンロード。ファイル名は時刻（時分秒）まで入れ、meta の行に書き出した時刻と端末（iPhone・Mac など）を入れる。読み込みの窓で「書き出した時刻・todo の件数・端末」を見せ、別の端末の CSV の取り違えに気づけるようにする
- 作り: `js/csvio.js`（toCsv・readCsv・importInto）、`js/screens/settings.js`（csvBox・askMode）。テスト `node tests/csvio.test.mjs`

## 引っ越し（暗号化したファイル。2026-11-07 Issue #19）

CSV は開いている海だけで、サーバーに入る鍵も入らないので、端末を変えると共同 TODO（招かれた海）を戻すには持ち主に招待コードを頼むしかなかった。
設定の「引っ越し（暗号化したファイル）」は、**すべての海の記録と、サーバーに入る鍵を1つのファイルにして、合言葉で暗号化する**。
ブロックチェーンへの書き出しは検討したうえで使わない（消せない・公開される・暗号資産を買う手間。Issue #19 のコメント）。

- **中身**: 個人と一覧にある海の記録（この端末に箱があるもの）・海の一覧・サーバーの住所と入る鍵。
  公開の形（パスキー）は「引っ越しの鍵」、手元の形（合言葉）は自分の合言葉と「共有」の合言葉。
  AI のキー・パスキーの通行証・端末だけの設定は入れない
- **暗号**: app が作る合言葉（24 字。招待コードと同じ 32 種の字で 120 ビット）→ PBKDF2-SHA256 60 万回 → AES-256-GCM。塩と IV は毎回新しく作り、ファイルの頭に平文で置く。
  鍵はどこにも置かない（合言葉を忘れたら開けない）。WebCrypto だけで書く
- **作る**: 「引っ越しのファイルを作る」→ 合言葉が出る → 書き留めてから「ファイルを保存する」（スマホは共有シート。暗号の計算のあとに共有シートを出すと iPhone が断ることがあるので、ボタンを分けた）
- **開く**: 新しい端末で「引っ越しのファイルを開く」→ 合言葉 → 確かめて戻す。記録は消さずに重ねる（merge.js。同じファイルを2回読んでも増えない）。
  公開の形なら続けて「サーバーに入る（この端末のパスキーを作る）」で、引っ越しの鍵を招待コードの代わりにして登録する。
  ほかのサーバーに繋いでいる端末では、サーバーの設定は変えない
- **引っ越しの鍵**（`server.py` の `POST /api/passkey/move`、`passkey_store.py` の `add_move_key`）:
  - パスキーで入っている端末が、ファイルを作るたびにサーバーから受け取る。入れる範囲はその端末のパスキーと同じ（個人の番号も同じ）。サーバーには sha256 だけ（`invites.json` の `kind: 'move'` の行）
  - 1つのパスキーに1つだけ。作り直すと前の鍵は使えない（＝最後に作ったファイルだけでサーバーに入れる。記録は前のファイルからも戻せる）
  - 使い切り。新しい端末で使ったら、次のファイルはその端末で作り直す。期限は 10 年
  - 置き場がいっぱい（3台）なら、鍵を作った端末（引っ越す前の端末）のパスキーを外して登録する。空きがあれば前の端末もそのまま
  - 鍵を作った端末のパスキーを `passkey-remove` しても鍵は残す（失くした端末からの引っ越しに使うため）。ファイルと合言葉が漏れたら `python3 server.py move-remove <名前>` で消す。`invite-list` に「引っ越しの鍵」として出る
- まだ確かめていないこと: 本物の端末（iPhone・Android）での共有シート・パスキーの登録・PBKDF2 60 万回の待ち時間
- 作り: `js/movefile.js`（暗号・中身・重ね方）、`js/screens/settings.js`（moveBox）、`js/passkey.js`（makeMoveKey）、`js/sync.js`（moveSecrets）。

### 共有の海（掲示板。2026-11-11 Issue #37。試し）

利用者の返事「おすすめで」で決めた順: **段1** 掲示板の部品と、特定の複数人で共有する海（この節）→ **段2** チャット（メッセージ。2026-11-11 段1への返事「OK」で作った。下の「チャット」）。
誰でも読み書きできる公開の掲示板は今は作らない（書かれたものを消せず、誰が書くのも止められないため。段2のあとで決める）。

- **掲示板** = チェーンの上のアドレス 1 つ。書く取引に「載せるだけの口座」として入れ（どの命令にも渡さない。Memo に渡す口座は署名者でなければならないため）、
  読むときはそのアドレスの取引の一覧（getSignaturesForAddress）を見る。`chain.js` の `memoMessage` の `extra`。
- **書くのは止められない**ので、読む人は暗号で、書く人は署名で限る。書き込みの中にウォレットの Ed25519 の署名を入れ、
  持ち主が書いた名簿にあるアドレスの書き込みだけを使う（名簿に無い人の書き込みはチェーンには残るが、画面に出さない）
- **海の鍵**（32 バイト・海ごと）から、掲示板のアドレス（HKDF → Ed25519 の公開鍵）と掲示板のカギ（AES-256-GCM）を作る。
  端末には自分の記録のカギで包んで置き（`bubble_todo_board_v1`）、使うたびにパスキーか合言葉で開く
- **渡すのは共有用のアドレスだけ**（`BTA1-…`。X25519 の公開鍵＋ウォレットの公開鍵。人に見られてよい。利用者の返事「鍵のやり取りはしないで、渡しても安全なアドレスだけで」）。
  X25519 の鍵は元から HKDF(元, "share") で作るので、新しく覚えるものは無い。パスキー・合言葉を替えると共有用のアドレスも変わる（招き直しが要る）
- **招待（封筒）**: 持ち主が、使い捨ての X25519 と相手の公開鍵で鍵を合わせ（ECDH → HKDF → AES-GCM）、海の鍵を包んで、相手のウォレットを載せた取引に書く（`bt2e <base64>`）。
  中に持ち主のウォレットの署名を入れる（名をかたった封筒は捨てる）。共有を始めたときは自分宛ての封筒も書く（自分のほかの端末が受け取れる）
- **外す**: 持ち主が海の鍵を作り替え（代 +1）、残る人にだけ封筒を書き直し、新しい掲示板に名簿と自分の記録を書く。
  外した人は、それより後の記録は読めないが、それまでの記録は読める（チェーンの上のものは消せない）
- **保存・読み込みはボタンで**（押したときだけ手数料）。保存 = その海1つの記録の写し（`bt2` の切れ端。形は `bt1` と同じで、AAD が違う）。
  読み込み = メンバーごとにいちばん新しい写しを、`merge.js` で記録ごとに新しいほうを残して重ねる。写しの中の海の ID は見ず、その海の箱にだけ重ねる
- **見えるもの**: 誰と誰が同じ海にいるか（持ち主のウォレット → 招かれた人のウォレットへ封筒が書かれる）、書いた時刻と大きさ
- **チャット**（段2）: 共有中の海ごとの「チャット」と、自分の端末どうしの「自分あてのメモ」。
  - メッセージは記録の写しと**別の掲示板**に書く（`chatBoardOf`。海の鍵か自分の記録のカギから HKDF で作る）。同じ掲示板だと、メッセージが増えて読み出しの件数から写しが押し出されるため
  - 1 件 = 署名した `{ kind: 'msg', sea, g, at, text }`（300 字まで）。縮めて暗号化し、取引 1〜2 件。書いた人が手数料を払う。確かめの窓は出さない（チャットのたびに出ると使えないため。手数料が掛かることは欄の下に書く）

## 気孔（隠れている泡を呼ぶ）

2026-10-25（利用者の指示）。海は画面に収まる数だけを新しい順に浮かべ、残りは隠れる。隠れている泡があるときだけ、海の底の右に気孔（横から見た岩の小山）が出て、口からいつも小さな泡が昇る。
- 気孔をタップすると、隠れている泡が1つ気孔から生まれてふくらみながら海に入り、**そのとき画面でいちばん上に居た泡**が押し出されて上ではじける。押し出された泡は隠れる側の最後へ回る（続けて押すと順に回る）。ほかの泡は下から押されたように少し揺れる
- 数は出さない。ボタンの枠も文字も無い（読み上げにだけ「隠れている泡を1つ呼ぶ」）。前の「新しいほうから出している」の1行はこれに置き換えた
- 入れ替えた並びは面ごとに持ち、新しく書いた泡・別の海から来た泡が出たとき・海の画面を離れたときに捨てて、いつもの「新しいほうから」に戻す
- 作り: `js/screens/sea.js` の `swaps`・`swappedKeep`（capForSea）・`swapOne`、`css/screens/sea.css` の `.sea-vent`。動きの試作は AI_note 側（GitHub には無い）

## 優先度（急ぐ・大事）

2026-10-25（利用者の指示。Eisenhower のマトリックス。デザイン案の A と B を両方）。
- 盤に「◷ 急ぐ」「◆ 大事」の2つの切り替えと、今の区分の名前。閉じるときに書く。「印を外す」で「まだ」に戻す。片方を押すと、押していない側は「いいえ」になる（片方だけ「まだ」だと区分が出ないため）
- 「⊞」（海はフィルターの隣、今日はさいころの左。2026-10-25 にフィルターの中から外へ出した）で、泡を 2×2 の区分にする（左右＝急ぐ／急がない、上下＝大事／大事でない）。下の点線の帯が「まだ分けていない」。泡を区分へドラッグすると印が付き、帯へ戻すと外れる。もう一度「⊞」で戻る
- 形は `js/quadview.js`・`css/quad.css`（海と今日で共有）。海ではリスト表示のもう1つの形として出し入れする（「もどす」でも戻る）。今日では漂う面を降ろして、その日の泡を並べる（‹ › で日を移しても分けたまま）

- 出さないもの: 区分ごとの数・割合、赤、命令形の名前。急ぐを日付から自動で付けることもしない
- 記録: todo の `urgent`・`important`（true / false / null＝まだ）。旧データは null。区分の名前と並びは `js/priority.js`

## 海（個人と、名前を付けた海）

1つのサーバーが預かる海のまとまりを「海域」と呼ぶ（上の「海域」の節）。

2026-11-02（Issue #4。利用者の指示：「共有」ではなく、海に名前を付けて複数作れるように。返事は「1A・2 引き継ぐ・3 色を選ぶ」）。
いちばん上の薄い帯（30px）に海の名前が並び、今の海が白く浮く。帯の名前か、左上の ≡（引き出し）のいちばん上の名前を押すと切り替わる
（画面を読み直し、app 全体＝海・今日・きっかけ・すきま・ふりかえりがその海の記録になる）。海が多いときは帯を横に流す（端はぼかす）。
帯は 30px のまま、押す的だけ 44px（2026-10-24 に 54px の帯から考え直した。デザイン案の B と D。2026-10-25 Issue #3 で帯からも押せるようにした）。

- **個人**: 最初からある海。名前を変えられず、消せない。水は空色のまま
- **共有**: 前の版の「共有」。記録（端末の `bubble_todo_share_v1`・サーバーの `share/`）をそのまま引き継ぎ、名前と色を変えられる海の1つになった（既定の名前は「共有」、色はマグマの赤）

## 利用（clone して使う側）

この repo を clone したフォルダで使う。clone 側では直さず、開発側で直してコミットし、clone 側の `update.command`（`git pull --ff-only`）で取り込む。

- 正本: clone の `data/state.json`（server.py の記録。サーバーに繋いだ端末の記録が集まる）。各ブラウザの localStorage にも同じ記録が入る。
  サーバーに繋いでいない端末の記録は、その端末の localStorage にだけある（サイトデータを消すと消える）。
- 起動: `start.command` をダブルクリック。空きポート（既定 8931、環境変数 `BUBBLE_TODO_PORT` で変えられる）で clone の `server.py` を起動してブラウザを開く。
  記録は clone の `data/` に入る。初回に合言葉を作って画面と `data/token.txt` に出すので、設定の「サーバー」で「このページのサーバー」と合言葉を入れて繋ぐ。
  ES モジュールなので `file://` では動かない。
- 置くもの: 起動口のほか、Android ビルド用の実値の `.env`（`.env.example` の写し）があれば clone 側。Android ビルド自体は開発側で行う（`node_modules/` `android/` `www/` は clone 側には作らない）。
- 公開版は GitHub Pages（上の「動かしてみる」）。そちらの記録はそのブラウザの localStorage に入る。

## 枝の扱い（2026-11-07。利用者の指示 Issue #20）

ふだんの作業は `main` にじかに積む（利用側の clone とサーバーは `main` を `git pull --ff-only` で取り込む）。
別の枝を作るのは、試作（例: 公開・パスキーの形）と見比べ用の候補（例: Issue #2 の A・B・C）だけ。

- **点検**: `node tools/branches.mjs`（origin を fetch して、main 以外の枝ごとに main より先・遅れの数と目安を出す。書き換えはしない）。
  Issue を直すセッションの終わりに回し、枝が残っていたら下のとおり片付ける
- **取り込み済み**（main より先が 0）: `archive/<枝の名前>` の札（tag）を付けて push し、手元と origin の枝を消す
- **未取り込み**: 中身が要るなら main に取り込む（早送りか merge）。見比べ用など main に入れないと決まったもの（Issue が閉じた候補など）は、札を付けて消す
- 消した枝は札から戻せる: `git switch -c <枝の名前> archive/<枝の名前>`

## 既知の不具合（未修正）

記録はブラウザの localStorage にあり、localStorage はオリジン（host:port）ごとに分かれる。次の2つで、記録が「消えた」ように見えることがある（2026-09-25 にコードで確認。2026-11-02 にも残っていることを確かめた）。

- `start.command` は既定のポート（8931）が塞がっていると、警告を出さずに次のポートへ逃げる。ポートが変わると別のオリジンになる。塞がっているときだけ次のポートで開き、警告を出すのがよい。
- `127.0.0.1` と `localhost` も別のオリジン。開発補助の `serve.py` は `localhost` と表示し、`start.command` は `127.0.0.1` を開く。
